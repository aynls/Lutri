# Lutri 产品需求

Lutri是面向专业创作者的桌面AI生图工作台。
包含创作、超分辨率、任务和图库四大核心功能。“任务”同时承载生图任务进度和历史记录。

## 创作

用户选择模型和供应商，开始创作流程。
创作页提供“常规”和“批处理”两个工作视图，共用左侧的提示词、参考图和参数编辑器。视图切换位于左侧面板顶部、模型选择器上方，使用与超分辨率页面一致的整行等宽分段控件。常规视图右侧显示瀑布流，主操作为“开始生成”；批处理视图右侧显示待提交清单，编辑器主操作为“加入清单”，清单底部提供“提交批处理”。批处理用于积累多组提示词或参数后统一提交，不作为常规生成按钮旁的开关。

切换视图时保留提示词和参考图，尽力保留参数。进入批处理视图时，当前模型与供应商组合支持批处理则继续使用；否则优先选择同一模型下已配置的批处理供应商，再选择最近使用的可用批处理组合，最后使用预设的支持组合。切换结果直接体现在模型选择器和参数控件中，不额外显示解释性提示。没有已配置的批处理供应商时，仍允许准备草稿，提交前再要求完成配置。

参数仅在含义相同且符合目标组合约束时沿用，其余使用目标组合已保存的值或默认值。参考图数量超限或用途不兼容时保留输入并提示修正，不静默删除图片或改变原图、区域、蒙版的绑定对象。返回常规视图时恢复此前的常规模型与参数，保留最新提示词和参考图，并重新检查约束。切换仅影响编辑器，不改写已加入批处理草稿的条目。

### 常规生成

常规视图右侧是列宽固定的瀑布流，展示了之前生成过的图片。
生成过程中，右侧瀑布流从上到下展示对应的卡片。
提交一个生图 API 请求时，对应的瀑布流卡片被创建，此时展示加载动画。同时右上角有一个计时器，表示从提交请求开始已经过了多久。当取得生成结果时，开始下载，计时器位置变化为文字“正在下载”，结果区域显示各张图片的下载状态。下载失败的图片显示淡红色“重试”图标；已成功保存的图片正常展示。

请求需要区分提交中、提交结果未知、生成中、结果获取失败、结果下载中、结果下载失败、已完成和生成失败等状态，并保存恢复原任务所需的任务标识、查询信息和已取得的结果信息。轮询中断或超时而供应商仍有未取得的结果时，显示“结果获取失败”；已有图片继续保留，重试继续查询原任务。只有已取得地址的图片保存失败才属于“结果下载失败”。

生图卡片上的“重试”只继续获取原任务的结果，不创建新的生成任务。已有可用结果地址时直接重试下载；需要查询任务状态或重新取得结果地址时，恢复原任务的查询或轮询。若无法查询原任务或取得结果，显示原因，不自动重新生成。

每张瀑布流卡片对应1张图像。如果一次请求同时生成多张，会创建多个卡片。

点击卡片，在覆盖主窗口大部分区域的应用内模态弹窗中展示图片和相关信息。图片加载期间显示与生图卡片一致的转圈动画；支持左右切图，关闭后保留原页面位置。

瀑布流的卡片都可以移除。清理瀑布流只移除卡片，不删除图库资产或历史记录，也不取消或中断后台任务。移除卡片后，任务仍按原流程保存结果，用户可以从历史记录查看状态或继续获取原任务结果。

瀑布流最多保留最近200个图片对应的卡片。超出上限时，较早的卡片退出瀑布流，处理规则与手动移除卡片相同。

### 模型与供应商

不同供应商提供同一模型时，可能支持不同的字段、取值、默认值和特殊能力。每个模型与供应商的组合需要明确定义其输入、约束和请求组装方式。通用控件和行为可以复用，但不能因此遗漏供应商特有能力。

Recraft Vector 使用独立模型入口，覆盖 V4、V4.1、V4 Styles 的普通与 Pro 矢量版本，按供应商实际可用组合注册。结果固定保存 SVG 原件并生成独立缩略图，不提供栅格输出格式或超分辨率。原厂支持单次 1–6 张；fal 和 Runware Vector 不提供单次数量参数，多图使用请求次数。Styles 的输入图用于风格参考；原厂 V4／V4.1 Vector 另有单图编辑路径。参数与供应商差异记录在 doc/model/Recraft/Recraft-Vector.md。

相关输入能力需要划分为细粒度、可组合的 React 组件，让后续可以对模型-供应商的组合做定制性的组件组合。对于一个特定的“模型-供应商”组合，支持的字段、约束和请求组装方式需要明确，并完整覆盖其 API 请求格式。

例如，提示词、参考图、输出尺寸、审核容忍度和联网搜索等。

图层拆分使用默认关闭的二态开关。开启后必须先选择图层另存为目录，手动提交和 MCP 提交遵循相同要求。供应商返回完整拆分结果后，自动将底图、透明图层及位置与层序清单保存到该目录下独立的子目录，再按返回的布局合成图片。图库、瀑布流和历史结果只管理合成图，不提供后续图层管理或另存为入口。图层保存或合成失败时保留原任务的恢复信息，重试不重新生成；成功后清理临时图层数据。

对生成和编辑路径分离、或具有独立图片用途的模型与供应商组合，提供“创作方式”选择。新草稿默认“生成”，添加参考图不自动改为“编辑”；“自动”保留按输入分流的行为，并用于兼容未记录创作方式的旧草稿及历史。统一接口且没有独立操作能力的组合不强制显示此控件。

“生成”将输入图用于参考创作；“编辑”明确选择编辑原图，其他输入图作为参考。编辑原图以参考图 ID 绑定，重排时不改变原图，提交时将原图排列在供应商要求的位置，并同步提示词、区域及蒙版引用。移除或丢失原图后不得自动替换为另一张图。切换方式保留已有输入；不兼容的蒙版、风格或数量设置须修正后提交。原图下拉框只列实际图片；进入编辑模式或首次添加图片时默认选择第一张。

创作方式与接口路径分别处理。GPT Image 保持 Images API，带参考图时仍使用 edits；参考创作和编辑原图通过明确的提示词表达意图，不表示原生 action 参数。支持原生参考字段时使用原生字段：Recraft V4.1 风格生成使用 style_reference_urls，Nano Banana 2 / Pro 的 fal 参考生成使用 context。创作方式和原图绑定随草稿与历史保存，MCP 与界面共用校验及请求组装。

组件的组合方式需要依照模型-供应商关系决定。每个模型在独立目录中以 TypeScript 定义各供应商的字段、组件组合、约束和请求组装方式。对于一些模型的特有能力需要单独设计组件，例如“包围盒”（flux3）。

填写必要参数并满足对应模型、供应商与提交方式的 API 参数约束后，常规生成可点击“开始生成”，批处理可加入清单。可选字段按对应组合的规则使用默认值或省略。

用户可以设置“请求次数”，决定当前配置发送多少次参数相同的生图 API 请求。如果模型与供应商支持在单次请求中指定生成数量，用户可以设置“单次生成数量”，并按该组合的约束进行校验；否则不显示该设置。这两个控件相邻展示，明确区分请求数与图片数，例如“4 次请求 × 每次 2 张”。批处理的每条配置分别保存这两个值，应用不根据预计总张数自动改变请求次数或单次数量；失败重提以原请求为单位，保留单次数量。

一次常规生成提交形成一个请求分组，点击“开始生成”和通过 MCP 提交均遵循此规则。该分组仅用于聚合记录，不表示使用供应商的 Batch API。常规单次提交的请求次数设有可配置的上限，默认 20，可在设置中调整，最小为 1，手动提交与 MCP 提交共用同一上限；批处理整批数量按其提交规则校验，不套用常规单次提交的上限。

每个请求可以产生一张或多张图片，每张结果图片拥有独立的 asset ID。任务页按每次提交聚合展示，并保留每次请求的参数和状态；实际结果数量以供应商返回为准，部分失败时如实显示实际成功数量，不自动追加生图请求补足数量。

参考图添加时默认使用“参考图”作为本次创作中的临时别名。别名左侧常驻显示重命名图标，用户可修改别名。提示词中用户可以一键插入参考图的别名，并且在提示词输入框内参考图字段会用胶囊式图标显示。
参考图的顺序有意义。调整顺序时，需要同步提示词、区域或蒙版中对图片的引用，避免操作作用于错误图片。绑定的图片丢失或不可访问时，对应的区域或蒙版设置一并移除，并提示用户。
在用户提交请求时，如果提示词中的参考图字段没有对应的参考图，显示警告弹窗。

### 批处理

首期支持 Google 和 OpenAI 的原生异步 Batch API。批处理能力按“模型 × 供应商 × 提交方式”明确定义，只有官方支持且已实现对应请求格式的组合可选；供应商支持批处理不代表其全部模型、操作或参数都支持。能力核对以 [Google Batch API](https://ai.google.dev/gemini-api/docs/batch-api) 和 [OpenAI Batch API](https://developers.openai.com/api/docs/guides/batch) 官方文档为准，具体字段及约束同步记录到 doc/model。

批处理复用通用输入控件，但使用独立的请求组装和任务执行流程。常规接口与批处理接口不同的字段必须明确映射；不支持的能力不得通过静默丢弃用户设置来提交，也不得自动改为常规生成。

#### 草稿与编辑

待提交清单是一份批处理草稿，包含按加入顺序排列的多条创作配置。“加入清单”保存当前提示词、参考图及绑定关系、模型、供应商、参数和请求次数的独立副本。加入后保留编辑器内容供继续修改，后续修改不影响已加入的条目。草稿及尚未加入清单的编辑内容自动保存，关闭应用后可恢复。

清单行只展示模型、供应商、提示词摘要、关键参数和请求次数，提供编辑、复制、移除操作；详细参数沿用左侧编辑器，不在每行重复展开整套表单。不按供应商重新排列条目，后台拆分也不改变用户看到的顺序。清单汇总配置条数与请求总数，预计图片数与实际结果数明确区分。

编辑条目时，左侧主操作变为“保存修改”和“取消”，原先尚未加入清单的编辑内容暂存；保存或取消后返回原编辑内容。未保存的修改不得被整批提交跳过，须先保存或取消才能提交。编辑期间切换页面或工作视图时，单独暂存条目编辑内容，返回批处理后继续编辑，不将其自动保存、丢弃或作为新条目加入清单。

“自动另存为”和“写入图库”放在清单底部的“提交批处理”旁，作为整批保存设置随草稿保存，不放在“加入清单”旁，也不在每条配置中重复设置。开始准备下一批时沿用这些保存设置。

#### 提交与执行

点击“提交批处理”后，先校验整份草稿的配置、参考素材、凭据、保存目录及供应商的请求数量和文件大小等约束；错误定位到对应条目，本地校验未通过时不发送任何生成请求。提示词缺失引用沿用现有警告规则，允许用户确认后继续。清单为空时不能提交。

校验通过后，将本次条目、顺序和保存设置固定为不可修改的配置快照，持久化任务记录与提交状态，再将这些条目移出草稿并开始远程提交。此后编辑草稿不影响已提交任务，用户可以继续准备下一批。提交操作按同一份快照防止重复触发；尚未确认远程是否接受的请求不得直接重新发送。

应用按供应商、账号、模型、接口路径及容量限制将一次提交拆成必要的远程批次。用户仍看到一条提交记录和原有条目顺序，拆分信息仅在详情中展示。各请求使用稳定标识关联原条目，不依赖供应商返回结果的顺序。

部分远程批次已接受、部分提交失败时，显示“部分提交”，保留全部条目的独立状态。重试提交只处理明确未被接受的部分；提交结果未知时先核对原任务，无法核对则显示原因并保留恢复信息，不自动重复提交。已接受的部分继续执行和保存结果。

提交后留在创作页，用简短状态反馈提供“查看任务”入口，打开“任务”的“批处理”标签。批处理的占位、进度和结果均不进入常规瀑布流；结果在任务详情中查看，是否同时进入图库由提交时的保存设置决定。

任务状态区分提交中、提交结果未知、云端排队、处理中、获取结果、保存结果及终态。展示供应商提供的真实请求进度，并将处理完成的请求数与已保存图片数分开；未知进度不显示虚构百分比或倒计时。云端处理结束后仍须获取并保存结果，全部请求成功且结果在本地保存完成后才显示“已完成”；部分成功、失败和取消分别保留真实状态与已有结果。

远程任务已接受后不依赖应用持续打开。重启后恢复查询和结果保存，不重新提交生成请求；网络中断或结果获取失败不等同于生成失败。“继续获取”只查询原任务或下载已有结果；需要重新生成时，用户明确将所选配置“重新加入清单”，再提交新的批处理。供应商结果已过保留期或无法恢复时显示原因，不承诺无限期取回。

取消已接受的远程批次后显示“取消中”，直到供应商确认，保留已产生的结果。取消不保证已处理部分不计费。常规生成的“停止剩余”仅停止本地尚未发送的请求，与云端批处理取消分开处理。

### 提示词生成

用户的提示词编辑框旁边始终有一个“生成”按钮。点击后进入一个单独的提示词生成页面。每次打开时，创作页当前的提示词和参考图都会同步到 Writer。Writer 复用创作页的提示词编辑器和参考图控件，支持胶囊显示与快捷插入、添加、移除、排序及重命名。进入后用户可独立编辑；采用生成结果时，提示词和对应的参考图配置一并带回创作页。

发送给 LLM 的提示词由三部分组成：

1. 系统提示词：由应用维护，用于规定 LLM 的任务和输出要求，不向用户展示，也不提供编辑入口。
2. 用户输入：用户在提示词生成页面编辑的内容。
3. 附加规范：每份规范是一个 `.md` 文件，其内容作为 LLM 的写作参考。选中的各份规范按列表顺序，以独立段落分别追加到请求末尾。

应用内置若干规范，内容来自各生图模型系列的提示词最佳实践。用户也可以导入自己的 `.md` 文件作为规范，并选择本次请求需要附加的规范。

用户在此页面可以管理一个“作家队列”，包含了一个或多个模型配置。可以重复。发送提示词生成请求时，每个作家都会撰写一份提示词，之后以多个卡片的形式展示在右侧。需要支持模型推理过程和生成内容的流式传输。

作家配置窗口提供“检测思考强度”按钮，从供应商的模型列表发现该模型支持的档位并展示结果；保存仅持久化当前配置，不触发检测。检测失败或未返回档位时视为不支持，不发送思考强度参数。修改端点、模型或密钥后清除检测结果；检测可使用尚未保存的密钥，但不会保存密钥。发现档位后可在队列中选择，同一作家的选择会被记住；选择供应商默认时不发送该字段，否则在请求中发送 `reasoning_effort`。重写沿用结果原来的强度，当前配置不再支持时回退到供应商默认。

用户可以对一个卡片点击重试按钮，让对应作家重写；或者点击确认，使用该卡片的提示词内容。

Writer 仅支持具备图片输入能力的模型，模型配置窗口显示此提醒，不提供图像输入开关。已经添加的参考图会发送给所有作家。每张图片前附带引用标记、临时别名、asset ID 和图片序号，明确 `[[ref:ID]]` 对应紧随其后的图片；要求 LLM 在输出中保留引用标记。

### FLUX 3 Image 示例

FLUX 3 Image 的同一接口支持生成和编辑，具体用法由提示词和参考图等实际输入决定。表单需要覆盖该模型和供应商支持的字段，包括提示词、参考图、输出尺寸、审核容忍度和联网搜索等。完整参数及约束见 [FLUX 3 Image API](model/FLUX/flux-3-image/flux-3-image.md)。

## 超分辨率

“超分辨率”页面：默认处理单图，右侧显示图片，左侧toolbar显示要使用的模型、倍率、输出位置、是否保存到图库等。
超分辨率操作不进入“任务”页面；此处的批处理是本地超分辨率队列，与生图的云端 Batch 分开管理。
SVG 不支持超分辨率。图库和图片查看器禁用 SVG 的超分入口；超分页面添加图片时，若选择中包含 SVG，则提示并拒绝整批添加。后端在任务入队前按图库资产的实际媒体类型拦截 SVG，MCP 调用遵循相同规则。
用户可以在toolbar中点击切换到批处理模式：批处理模式下，toolbar不变，右侧变为多张图片的卡片网格排列。

单图模式下完成后，右侧可拖动手柄查看前/后超分辨率效果对比。
批处理模式每个卡片的进度独立。点击卡片复用通用图片查看器，支持批次内前后切换、缩放，以及完成后的前/后超分辨率效果拖动对比。查看器中的图片操作针对超分结果；未完成时显示原图与当前任务状态。

超分辨率结果是新的图片资产，保存到图库时进入“生成结果”库，并获得新的 asset ID，不替换原图资产。除按设置保存外，完成后也可以一键保存到图库。
单图、批处理卡片与查看器均可将完成的超分结果直接用作创作参考图。结果未入库时先保存为生成结果资产，已入库时沿用其 asset ID；仅查看和对比不触发入库。参考图添加成功后返回创作页，失败时保留当前页面与结果。
已取消或失败的任务点击重试后立即重新加入队列，无需再次点击超分辨率按钮；执行顺序与并发数由同一队列控制。

## 任务

原“历史”导航入口改为“任务”，同时展示进行中的任务和历史记录。页面提供“常规”和“批处理”两个标签，各自独立查询并保留筛选条件与滚动位置；不另设批处理管理页面。两个标签均支持按时间、模型、供应商、状态、提示词和 asset ID 查询，批处理历史可直接定位，无需从常规记录中逐条辨认。

每次提交显示为一条默认收起的记录，摘要包含提交时间、状态、配置或请求数量及实际结果数量。展开常规记录后查看各次请求；展开批处理记录后按草稿原顺序查看配置及其请求、结果。每次请求保留模型、供应商、可恢复的完整业务参数和状态，以及各张结果的下载、保存状态。远程批次与请求标识放在详情中，不作为主列表的层级。

图片输入以 asset ID 引用替代图片内容，保留用途、顺序及绑定关系；生成结果也按顺序保存 asset ID 引用。历史不保存图片副本或包含图片 Base64 内容的原始请求体，不依赖临时图片地址恢复参数。恢复后再次提交时，根据业务参数和可用的图库资产重新组装请求。

用户可以一键恢复历史请求参数，包括可以找到的参考图。如果引用的图库文件已经丢失或不可访问，其他参数仍然恢复，缺失参考图保留原 asset ID、位置和缺失占位，并明确显示提示弹窗。恢复后的表单中，缺失图片绑定的区域或蒙版设置一并移除。

恢复参数沿用同一套创作编辑器，并进入记录对应的工作视图，不自动提交。批处理支持将所选配置重新加入清单，新草稿与原任务记录相互独立。仅重新加入生成失败项时，按失败请求数建立条目，不重复加入已成功的请求；仅结果获取或保存失败的请求使用“继续获取”，提交结果未知的请求须先核对状态。已有未保存编辑内容须保留或由用户明确处理，不因恢复历史而丢失。

恢复及再次提交时，应保持剩余图片与提示词引用的对应关系；缺失引用不得因剩余图片重新编号而指向其他图片。提示词中的缺失引用沿用提交前警告、允许用户继续提交的规则。

历史记录和图片文件分离，记录中的图片只保存 asset ID 引用。如果源文件丢失，显示占位标识和提示。

历史记录支持查看任务状态，并按与生图卡片相同的规则继续获取原任务结果；对应卡片被移除或退出瀑布流后，此入口仍然可用。

批处理结果复用通用图片查看器及复制、另存为、用作参考图等操作。关闭“写入图库”时，仍可在任务详情查看和使用本地结果；不通过瀑布流提供第二个批处理历史入口。

提交中、提交结果未知、云端排队、处理中或取消中的记录不能直接删除，以免丢失查询与恢复入口。云端已结束但存在待获取或待保存结果时，删除须明确提示将失去继续获取入口；未入库结果仅能通过该记录访问时，也须提示删除后的访问影响。删除记录不等于取消远程任务，不连带删除图库资产。

按 asset ID 搜索时，匹配记录中的参考图或生成结果引用。用户从图库点击“查找相关历史”，进入任务页面并自动查询；已知生成来源时打开对应标签，否则沿用当前标签，切换标签时保留此次 asset ID 查询条件，两个标签均可查找相关记录。也支持复制 asset ID 后手动搜索，没有匹配记录时显示空结果。

## 图库

图库包含“生成结果”“参考素材”“收藏”三个默认库，此外还可以有用户的自定义图板。可以在“全部”中查看所有库的图片。

其中“生成结果”和“参考素材”按资产来源分类，两者无交集。生图和超分辨率产生的结果属于“生成结果”，外部导入的图片属于“参考素材”。图片在创作中被用作参考图，不改变其所属分类。

图库管理图片资产。从外部导入的图片复制到图库目录，进入“参考素材”库，不论原始来源是其他位置的文件还是剪贴板。每个图片资产由唯一的 asset ID 标识。

提交生图请求前，从外部添加参考图时，图片暂存为草稿素材，“创作”页面立即用 asset ID 引用，但不进入图库；提交常规生成或批处理时才导入图库“参考素材”。加入批处理清单只是保存草稿，不触发入库。清理未使用的暂存素材前，须检查常规草稿、批处理草稿的全部条目、暂存的编辑内容及未结束任务；只有不再被这些内容引用且未参与生成的素材才可清理。使用图库中已有图片作为参考图时，沿用原 asset ID，不重复导入，也不改变所属分类；生成结果用作参考图后仍属于“生成结果”。

生图结果下载完成后，按“写入图库”选项决定是否进入图库“生成结果”，历史记录通过 asset ID 引用它们。关闭入库时，图片与缩略图仍保存到图库目录下的原有位置，仅在独立的结果索引中保留读取文件所需的信息，不创建图库记录；任务详情、图片查看器、复制、另存为和参考图引用仍可使用这些结果，常规结果也可在瀑布流查看。批处理结果不进入瀑布流。未入库结果不参与图库列表、搜索、统计、收藏、图板或自动清理，作为参考图使用也不自动入库。

常规生成和超分辨率的主按钮上方提供两个独立复选框：“自动另存为”默认关闭，“写入图库”默认开启；批处理使用清单底部的整批保存设置，默认值相同。常规生成、批处理和超分辨率分别保存开关状态，共用另存为目录；开启自动另存为后展开目录选择控件，未选择目录时禁止提交任务，但不影响准备批处理草稿。设置页不再提供导出目录和自动导出开关。提交时固定入库选项与另存为目录，后续修改设置不影响已提交任务。每张结果保存后按设置复制到另存为目录，无论是否写入图库；另存为失败保留原结果，可单独重试另存为。超分辨率关闭入库时沿用独立的结果文件位置，仍可查看对比或手动保存到图库。

图库中可以有“图板”功能，用户可以组织图板，包含一组选定的图片。收藏和图板使用已有资产的 asset ID，不创建图片副本，也不改变其“生成结果”或“参考素材”分类。

图库中已有图片可以快捷被"创作"页面的添加参考图使用，或者在"超分辨率"添加。

图片格式在供应商结果解析中统一规范化，支持 SVG 的 MIME、格式字段、data URI 和 URL 后缀提示；无法确定时保留未知，不默认标记为 PNG。下载保存时按文件内容识别真实类型，图库保留 SVG 原文件及 PNG 缩略图，每张结果保存成功后将实际媒体类型回填到对应历史结果。

图库需要支持批量选中和另存为、删除功能。图库按照日期排序，且支持筛选功能。

asset id全图库唯一，用户可以一键复制。

图片资产不保存名称，界面不显示图片标题，必要时使用 asset ID 标识。图库只支持按 asset ID 搜索，不提供名称搜索或名称排序；MCP 同样不提供名称检索。

图库不保留每张图片的历史请求参数，也不直接恢复请求参数。图片提供“查找相关历史”入口，点击后进入任务页面并自动按该图片的 asset ID 查询，参数恢复在任务页面完成。图库资产不要求存在对应的生图历史记录，没有匹配记录时显示空结果；仍支持复制 asset ID 后手动搜索。

“生成结果”“参考素材”两个库可以分别开启或关闭自动清理，默认均关闭，关闭时不限制资产数量。开启后，清理容量按图片数量设置，必须为不小于30的整数。

被收藏或属于任意图板的 asset ID 不计入所在库的自动清理容量，也不会被自动清理删除。仅统计该库中未收藏且不属于任何图板的资产；超过设置的容量时，按入库时间从早到晚自动删除这些资产，直至数量降至上限。取消收藏且不再属于任何图板后，该资产重新参与计数和自动清理。

对已入库资产，常规草稿、批处理草稿和未完成任务的引用不提供额外的图库自动清理保护。此规则与未入库草稿素材的引用检查分开：图库按容量清理，暂存素材仅在不再被草稿或任务引用后清理。因图库清理而失去图片引用时，遵循图片缺失提示及对应区域、蒙版设置的移除规则。

## MCP

参考legacy项目设计，需要让agent拥有调用生图、查看结果、超分辨率、查找图库asset id的能力。

MCP 的 `generate` 发起常规生成，与手动常规提交使用相同的参数校验、请求次数、单次生成数量、请求分组、参考图导入、任务恢复、结果入库和历史记录规则，不随创作页当前视图改为云端批处理。每次提交形成一条常规任务记录，各请求的卡片与手动常规任务一起显示在创作页瀑布流中，并遵循相同的移除与数量上限规则。本期批处理入口在创作页，不扩展 MCP 的批处理提交接口。

`generate` 和 `upscale` 均支持 `autoSave`、`destination`、`saveToGallery`。省略时分别沿用常规生成和超分辨率的设置；显式参数仅覆盖本次提交，不修改界面设置。`autoSave: false` 关闭自动另存为；提供 `destination` 且未关闭 `autoSave` 时启用另存为。`autoSave: true` 未提供目录时使用共用目录，无可用目录则拒绝提交。`saveToGallery: false` 保留文件但不创建图库记录；未入库的创作结果仍可通过 `get_tasks` 取得 asset ID，再用 `get_image` 读取，`find_assets` 仅检索图库。

服务器以 Streamable HTTP 子集形式仅监听本机回环地址，使用 Bearer token 鉴权；token 保存在系统凭据管理器中并支持轮换，浏览器请求需携带与监听地址一致的 Origin。重复启动幂等返回现有端点，前端重载后自动恢复。

工具集分三组：生成由 list_models、generate、get_tasks、resume_task、cancel_batch 构成；图库与参考素材由 find_assets、get_image、import_image 构成；超分辨率由 upscale、get_upscale_jobs、cancel_upscale、list_upscale_models 构成。generate 异步提交后经 get_tasks 轮询，get_tasks 默认返回任务摘要，传入 taskId 时返回完整参数；upscale 同步等待完成，jobId 用于查询与取消。

`cancel_batch` 沿用常规请求分组的“停止剩余”语义，不用于取消供应商的云端 Batch。

## 技术方向

- 使用 Tauri、React、TypeScript 和 Rust 构建桌面应用。TypeScript 负责主要业务逻辑，Rust 负责桌面原生能力和高性能的超分辨率推理。
- 界面保持控件简洁、术语统一，返回和关闭入口持续可见；统一使用深色界面，支持暖砂、素灰、雾蓝、青瓷四种主题，以及赤陶、石墨、黛蓝、苔绿、琥珀、湖青、鸢紫、蔷薇八种强调色。主题与强调色独立选择并保存，不提供浅色模式或跟随系统切换；动画遵循系统减少动态效果的偏好。
- 严格禁止在UI中使用大量的无意义解释性文字。UI文案尽可能保持少。
